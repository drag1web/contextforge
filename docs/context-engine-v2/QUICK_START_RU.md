# Быстрый старт: как передавать пакет Codex

## Что находится в архиве

Архив содержит полный архитектурный baseline Context Engine v2:

- аудит текущего ядра;
- модель фактов, evidence, гипотез и findings;
- investigation loop и stop policy;
- границы модулей и ports;
- shadow-миграцию и rollout;
- validation model;
- поэтапные задания CE2-00—CE2-11;
- готовый протокол и стартовый prompt для Codex.

## Как работать

1. Положить содержимое архива в `docs/context-engine-v2/` отдельным коммитом.
2. Не смешивать этот коммит с незавершёнными изменениями старого selector.
3. Отправить Codex весь пакет для чтения.
4. В реализацию дать только **CE2-00**.
5. После ответа Codex проверить diff, тесты и архитектурные ограничения.
6. Зафиксировать контрольную точку.
7. Только затем дать CE2-01.

## Что отправить Codex первым

Открыть `CODEX_EXECUTION_PROTOCOL.md` и скопировать раздел:

```text
Ready-to-use initial prompt for CE2-00
```

Он уже содержит:

- список обязательных документов;
- точный scope;
- запреты;
- формат отчёта;
- условие остановки после CE2-00.

## Чего не делать

Не давать задание:

```text
Реализуй весь Context Engine v2 по этим документам.
```

Даже при наличии полного пакета реализация должна идти по одному work order. Полный архив нужен Codex для понимания будущих границ, а не для одновременной реализации всех этапов.

## Что присылать на аудит после Codex

Минимальный набор:

```text
ответ Codex
git diff --check
git diff --stat
git status --short
результаты stage-specific тестов
результат server build
архив ветки — если diff слишком большой для чата
```

Первый этап должен добавить только изолированные contracts, ports, skeleton application service и architecture guards. Он не должен менять production pipeline.
