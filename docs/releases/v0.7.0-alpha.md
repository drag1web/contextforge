# ContextForge v0.7.0-alpha — Desktop Workspace & Local MCP

ContextForge `v0.7.0-alpha` is a source pre-release that closes the large desktop workspace refresh and introduces ContextForge MCP Server v1.

## Highlights

### Local MCP Server v1

- Added a local stdio MCP server backed by the same SQLite storage and guarded Task Pack pipeline as the desktop backend.
- Added project, Project Memory, and saved Task Pack read tools, resources, and workflow prompts.
- Added explicitly authorized Task Pack creation with global opt-in plus per-call `confirmCreate: true`.
- Added bounded structured responses, stable `MCP_*` errors, safe provenance, path/secret redaction, and audit events that omit prompts and source content.
- Added generated Codex registration commands, `config.toml` snippets, connection testing, permission controls, and MCP documentation.

### Desktop workspace refresh

- Completed the redesign of Dashboard, Projects, Project Details, Scanners, Context Builder, Task Packs, Agents, Templates, Integrations, GitHub, Reports, Settings, and Account & Sync.
- Rebuilt Task Pack Builder and Result views, diagnostics, preview/edit flows, and archive interactions.
- Added a compact global toast system with process, success, warning, error, and information states.
- Refreshed the title bar, clickable product identity, version details, real AI status, Navigation Assistant, and Global Search.
- Completed Russian localization for Project Details and the refreshed navigation/search surfaces.

### Grounding and safety baseline

- Completed the universal grounding, canonical core, ownership, authorization, explicit-target, create-and-wire, supporting-context, and safety corrective passes included in the current source tree.
- Kept subjective, conflicting, conditional, incomplete, and unproven bug tasks in clarification, review, or investigation states.
- Preserved inspect-only supporting context without widening edit authorization.
- Kept diagnostics privacy-safe and excluded absolute local project roots from exported Task Pack metadata.

### Desktop Link and workflow integration

- Improved website pairing, device status, update checks, explicit Task Pack publication, inbox import, integrity checks, and failure acknowledgement.
- Kept project source, local paths, and generated files local unless the user explicitly publishes a selected Task Pack.

## Validation

The release gate includes:

- renderer and server build;
- MCP stdio handshake, discovery, permissions, shutdown, and storage smoke;
- Desktop Link smoke;
- Task Understanding and clarification smoke;
- Task Pack generation reliability smoke;
- selector rollout, ownership, canonical core, context quality, supporting grounding, authorization, safety, explicit create/wiring, and core freeze guard smoke;
- Validation Lab smoke where the local manifest is available.

Private real-project and sealed-validation results are never implied unless their maintainer-only manifests were present and actually executed.

## Privacy and permissions

- MCP is local stdio only.
- MCP reads registered ContextForge records and does not scan arbitrary directories on demand.
- MCP does not edit repository files, execute commands, mutate Git, or create pull requests.
- Task Pack creation is disabled by default and requires two-step authorization.
- GitHub and website account integrations remain optional.
- Diagnostics exclude raw prompts, model responses, source snippets, secrets, credentials, and absolute local paths.

## Known limitations

- This GitHub pre-release contains source code only; there is no installer or portable binary yet.
- Deep selector and ownership support remains strongest for TypeScript/JavaScript repositories.
- MCP v1 supports local stdio only; remote HTTP transport and OAuth are not included.
- ContextForge does not implement automatic code editing, Run in Codex, Codex App Server orchestration, automatic PRs, or automatic Git operations.
- Large renderer chunk optimization remains a later performance task.
